How it works — pattern learning, not role-switching

Old: ROLE: sales constraint in prompt, 9 roles stacked. New: No ROLE: label. Agent assesses situation type (e.g., problem state → support pattern effective) via learned association situation X → pattern Y from training data. Reward optimizes for task completion, satisfaction, accuracy — not role-adherence. Result: fluid, situational response without announcing roles.

RLHF framework → minimal_implementation/dpo_trainer.py · PPO/GRPO

🛡️

Guardrails still enforced — but learned, not prompted per role

Unified prompt still has FACTUAL GROUNDING: only claims supported by RELEVANT BUSINESS KNOWLEDGE, never invent price/availability. If not in KB → says so + offers human handoff. Gating now business-level only (capabilities toggles), not role-level. Training reward penalizes hallucination.

✦

Custom Agent Behaviour — your rules on top of learned patterns

Growth: 3 rules · Scale: 10 · Unlimited: ∞ · Launch: 0 (add-on $15 for 5). Builder lives in Admin & Portal → Custom Behaviour. Each rule: trigger (keywords/phrase/regex) → primary pattern + tone + instructions + priority + weightBoost. At inference, assessSituation() boosts your pattern when trigger matches; buildUnifiedPrompt() injects tone/instructions as “CUSTOM BEHAVIOURS”. Reward: still task/satisfaction/accuracy — custom is +10% bonus when triggered. No prompt hacks, no role labels.
